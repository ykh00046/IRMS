# 근태허가원 수집 연계 — 구현 계약

작성 2026-09-22. BRM(이 저장소)과 기존 포털 수집기(`C:\X\Server_API\webcloring-pdf`)가
이 문서를 공통 계약으로 삼는다. 이름·경로·필드를 바꾸려면 문서를 먼저 고친다.

## 1. 배경과 원칙

근태는 ERP 월 엑셀(`monthly_attendance_YYYY-MM.xlsx`)을 읽어 판정한다. 엑셀에 없는 정보는
추론으로 메운다(반차·반반차의 오전/오후). 결재 문서(근태허가원)에는 그 정보가 사실로 적혀
있으므로, 그것을 읽어 와 **보강 자료**로 쓴다.

원칙:

1. **판정의 근거는 계속 ERP 엑셀이다.** 허가원은 보강이며, 수집이 멈추면 BRM 은 종전대로 동작한다(fail-open).
2. **BRM 에 브라우저 자동화를 넣지 않는다.** 포털 로그인·검색은 이미 있는 수집기가 한다.
   수집기가 결과만 BRM 내부망 API 로 밀어 넣는다. 포털 자격증명은 BRM 에 두지 않는다.
3. **공용 PC 배려**: 개인 사정(종류·사유)은 책임자 화면에서만 본다. 공용 화면·트레이는 "결재 있음"
   수준까지만(기존 [[feedback_tray_privacy]] 원칙과 동일).
4. 1단계는 **적재와 대조까지만**. 오전/오후 확정·이상 자동 해소는 2단계에서 따로 결정한다.

## 2. 수집 대상 (수집기 몫)

- 문서함: **부서공개함**(기존 `box: dept_open` 경로 재사용).
- 검색: **작성자(기안자) 비움** + 문서제목 `근태허가원`. 기간은 마지막 수집 이후(기본 60일).
- 문서 종류: 반반차 · 반차 · 연차 · 예비군 훈련 · 그 밖(원문 그대로 보관).
- PDF·Excel 산출물은 만들지 않는다(이 수집기만 끈다).
- 목록 행에서 읽히는 값으로 우선 채우고, 부족하면 문서를 열어 본문에서 채운다.
- **실측(2026-09-22)**: 목록 칸은 문서번호·유형·분류·그룹사 여부·문서 제목·기안자·기안부서·완료일뿐이다.
  대상자·기간·오전/오후는 목록에 없어 **본문을 열어야** 한다. 본문의 `소속/사번/직위/성명`에서 대상자와
  사번을 얻고, `기간`의 시각으로 오전/오후를 가른다. **기안자와 대상자는 다를 수 있다**(팀장이 팀원 몫을 기안).
  결재상태 칸이 없어 `status` 는 사실상 늘 `완료`다. 부서공개함은 **수집 계정의 부서 문서만** 보인다.

## 3. 전달 규약

`POST /api/public/attendance-approvals` — 내부망 전용(`internal_only` 보호 접두 `/api/public`),
운영에서는 헤더 `X-IRMS-Tray-Token` 필요(기존 트레이 규약과 동일).

요청 본문:

```json
{
  "source": "portal",
  "collected_at": "2026-09-22T01:05:00Z",
  "items": [
    {
      "doc_no": "AP-2026-001234",
      "emp_name": "홍길동",
      "emp_id": "900033",
      "kind": "반차",
      "half": "오전",
      "start_date": "2026-09-25",
      "end_date": "2026-09-25",
      "status": "완료",
      "drafted_at": "2026-09-20",
      "title_raw": "근태허가원 홍길동 2026-09-25 반차(오전)",
      "doc_hash": "sha256:…"
    }
  ]
}
```

- 필수: `doc_no`, `emp_name`, `kind`, `start_date`. 나머지는 없으면 null.
- `half`: `오전` | `오후` | null. `kind` 는 원문 그대로(정규화 표는 §4).
- `doc_hash`: 수집기가 이미 쓰는 수정본 감지 해시. 값이 바뀌면 갱신한다.
- 배치 최대 200건. 200건 초과는 422.

응답: `{"received": n, "created": a, "updated": b, "unchanged": c, "rejected": [{"doc_no": "...", "reason": "..."}]}`.
거절은 400 이 아니라 목록으로 돌려준다 — 한 건이 나빠도 나머지는 적재한다.

## 4. BRM 저장·해석

표 `attendance_approvals`:

| 열 | 뜻 |
|---|---|
| `doc_no` TEXT UNIQUE | 결재 문서번호. 멱등 키 |
| `emp_name` TEXT NOT NULL | 대상자 이름(원문) |
| `emp_id` TEXT | 사번. 없으면 null |
| `kind_raw` TEXT NOT NULL | 문서의 종류 문자열 원문 |
| `kind` TEXT NOT NULL | 정규화: `연차` `반차` `반반차` `예비군` `기타`. 포털 종류 칸의 `훈련` 은 `예비군` 으로 접는다 |
| `half` TEXT | `오전` `오후` null |
| `start_date` / `end_date` TEXT | `YYYY-MM-DD`. end 없으면 start 와 같게 |
| `status` TEXT | 결재 상태 원문 |
| `drafted_at` TEXT | 기안일 |
| `title_raw` TEXT | 목록 제목 원문(사람이 대조할 근거) |
| `doc_hash` TEXT | 수정본 감지 |
| `source` TEXT NOT NULL | `portal` |
| `collected_at` / `updated_at` TEXT | 수집·갱신 시각 |

- 인덱스: `(start_date)`, `(emp_name, start_date)`.
- 사람 맞추기: `emp_id` 가 있으면 그것으로, 없으면 **이름 + 그 달 ERP 명단**으로 맞춘다.
  동명이인이면 맞추지 않고 `미매칭`으로 남긴다 — 조용히 아무나에게 붙이지 않는다.

## 5. 책임자 화면(1단계)

근태 책임자 월 화면에 '결재 대조' 구역을 둔다.

1. 그 달 허가원 목록: 날짜 · 이름 · 종류 · 오전/오후 · 상태 · 문서번호.
2. 대조 결과 두 갈래:
   - 허가원은 있는데 ERP 엑셀에 휴가 표시가 없는 건.
   - ERP 엑셀에 휴가가 있는데 허가원이 없는 건.
3. 미매칭(사람을 못 맞춘 건) 목록.
4. 수집 상태 한 줄: 마지막 수집 시각과 건수. 오래되면 눈에 띄게 알린다.

판정·알림·트레이는 1단계에서 **바꾸지 않는다**.

## 6. 검증

- BRM: 적재 멱등(같은 배치 두 번 = 갱신 0), 수정본 갱신, 필수 누락 거절 목록, 토큰 없으면 403,
  내부망 아니면 403, 대조 세 목록의 계산, 동명이인 미매칭.
- 수집기: 실제 포털 1회 수집으로 목록이 채워지는지, 기존 자재·PBHA 작업이 그대로 도는지.
- 개인정보: 공용 화면·트레이 응답에 종류·사유가 실리지 않는지 확인.
