# BRM 화면 표준 (UI Standard)

> 화면을 새로 만들거나 고치기 **전에** 읽는 기준. 프롬프트·요청보다 이 문서가 먼저다.
> 근거: 2026-09-08 화면 실측(하드코딩 색 500+건, 글자 크기 56종, AI 말투 문구 다수)과
> "레퍼런스 → 시스템 추출 → 문구 정리" 순서로 일하라는 디자인 원칙.
> 토큰의 단일 원천은 `static/css/common.css` `:root` 다. 여기 적힌 값이 다르면 CSS 가 맞다.

## 1. 이 시스템이 무엇인가

현장 공용 PC(마우스·저울·바코드, 장갑 낀 손)에서 **숫자와 표를 빨리 읽고 몇 번만 누르는** 제조
기록 화면. 마케팅 사이트가 아니다. 그래서:

- 설명보다 **값과 상태**가 먼저 보여야 한다. 안내문은 짧게, 한 번만.
- 색은 **의미**로만 쓴다(정상·경고·이상·정보). 장식 색·그라데이션·hover 리프트 금지.
- 한 화면에서 같은 뜻은 같은 모양이다. 화면마다 새 스타일을 만들지 않는다.

## 2. 색 — 역할 토큰만 쓴다 (hex 직접 쓰기 금지)

| 역할 | 토큰 | 용도 |
|---|---|---|
| 페이지 배경 | `--bg-page` | body |
| 표면 | `--bg-surface-100 / 200 / 300` | 패널·카드 / 조건 막대·강조 배경 / 표 헤더·비활성 |
| 입력 배경 | `--bg-base` | input, select, textarea |
| 글자 | `--text-primary / secondary / tertiary` | 본문 / 보조 설명 / 라벨·눈금 |
| 선 | `--border-subtle / strong` | 구분선 / 입력 테두리 |
| 브랜드(네이비) | `--accent-primary (+hover, -light)` | 주 버튼, 활성 탭, 링크 |
| 강조(오렌지) | `--accent-secondary (+hover, -light)` | 변경점·주의 표식·교체 경계. **한 화면에 한 군데** |
| 정상 | `--status-success / -bg` | 완료, 정상 판정 |
| 경고 | `--status-warning / -bg` | 확인 필요, 경고 판정, 미확인 |
| 이상 | `--status-error / -bg` | 이상 판정, 사용 금지, 취소 |
| 정보 | `--status-info / -bg` | 중립 안내 |

- 테두리 색은 `color-mix(in srgb, var(--status-…) 30%, transparent)` 로 같은 색조에서 파생한다.
- 근태 달력(`--cal-*`)·서명 잉크(`--ink-*`)·범주 팔레트(`--series-1~4`, 이어서 계량의 로트 열처럼
  "서로 다르기만 하면 되는" 색)만 예외 토큰이 있다. 새 예외는 만들지 않는다.
- 토큰에 없는 옅은 색이 필요하면 `color-mix(in srgb, var(--status-…) 35%, white)` 처럼 토큰에서 파생한다.
- 2026-09-08 회수: 화면별 CSS 의 hex 500+건을 전부 토큰·color-mix 로 바꿨다. `rgba(...)` 리터럴
  (반투명 오버레이·그림자, 약 100건)은 아직 남아 있다.
- 다크 모드 값은 `:root[data-theme="dark"]` 에 같은 이름으로 있다. 화면별 CSS 에서 색을 새로
  정의하면 다크에서 깨진다 — 이것이 hex 금지의 이유다.

## 3. 글자 — 스케일 토큰 `--fs-*` 만 쓴다 (`font-size: 13px` 같은 직접 값 금지)

| 토큰 | 크기 | 쓰임 |
|---|---|---|
| `--fs-display` | 3rem (48px) | 근태 시계처럼 멀리서 읽는 숫자 하나 |
| `--fs-hero` | 2rem (32px) | 제품 LOT, 지표 카드 값 |
| `--fs-xl` | 1.5rem (24px) | 합계, 모달의 자재명 |
| `--fs-lg` | 1.125rem (18px) | 패널 제목 `.panel-title`, 큰 버튼 |
| `--fs-md` | 0.9375rem (15px) | 표 셀, 입력값, 일반 문장 |
| `--fs-sm` | 0.875rem (14px) | 탭, 버튼, 부제 |
| `--fs-xs` | 0.8125rem (13px) | 필터 라벨, 칩, 안내 한 줄 |
| `--fs-2xs` | 0.75rem (12px) | 축 눈금, 시각, 부가 표기. **이보다 작게 쓰지 않는다** |

- 2026-09-08 회수 때 56종을 이 8단으로 스냅했다(12px 미만은 전부 `--fs-2xs`로 올림).
- 숫자는 `font-variant-numeric: tabular-nums`, LOT·코드는 `--font-mono`.
- 굵기는 400 / 600 / 700 셋만. 500 은 탭 활성에만.
- `line-height` 본문 1.5, 표·칩 1.3.

## 4. 간격·모양

- 간격은 `--space-1 … --space-12` (4px 배수)만. 임의 px 금지.
- 패널 안 여백 `--space-5`, 패널 사이 `--space-4`, 표 셀 `--space-2 --space-3`.
- 모서리: 카드·패널 `--radius-lg`, 입력·버튼 `--radius-sm`, 칩·탭 `--radius-full`. 6px·12px 같은 값 금지.
- 그림자는 `--shadow-subtle` 기본, 모달만 `--shadow-prominent`.
- 표는 `.table-wrap` 안에서만 가로 스크롤. 페이지 자체가 가로로 흐르면 안 된다.
- 모달은 `hidden` 속성으로 열고 닫는다(`display` 토글 금지).

## 5. 부품 — 있는 것을 쓴다

새 클래스를 만들기 전에 `common.css` 에서 먼저 찾는다.
`.panel .panel-title .panel-subtitle .panel-notice` · `.metric-card` · `.filter-group .filter-label .input`
· `.btn (.accent .compact .btn-sm .warn)` · `.button-row` · `.status-chip .status-*` · `.mgmt-tabs .mgmt-tab`
· `.table-wrap .blend-table` · `.trunc-note` · `.empty-state` · `.login-error`.
화면 전용 클래스는 화면 접두(`lh-`, `visc-`, `lau-`)를 붙이고, 공용 토큰만 참조한다.

## 6. 문구 — 사람이 쓴 한국어

AI 문체를 걷어내는 규칙. **모든 사용자 노출 문자열(템플릿·JS 알림·서버 detail)에 적용.**

1. **조사는 붙여 쓴다.** `LOT을`, `PB를`, `Excel로`, `48 이하`(숫자+단위·명사는 띄움). ✗ `LOT 을`
2. **줄표(—) 금지.** 문장은 마침표로 끊고, 나열은 가운뎃점(·)으로. ✗ `저장했습니다 — 목록으로`
3. **안내문은 한 문장, 40자 안.** 두 번째 문장이 필요하면 그 기능이 복잡한 것이니 화면을 고친다.
   배경 설명·설계 이유는 코드 주석으로 보낸다. 사용자에게 "왜 이렇게 만들었는지"를 말하지 않는다.
4. **버튼은 동사 2~4자.** `조회` `저장` `추적` `Excel`. ✗ `선택한 배합 기록에 점도 등록`
5. **상태는 명사, 판정은 결과 먼저.** `경고 · 하한 48 이하` 처럼 결론 → 근거. 느낌표·물음표 금지.
6. **"~하세요"는 행동 요청에만.** 정보 전달 문장은 `~입니다` 또는 명사로 끝낸다.
7. 영어 약어(LOT, DHR, ERP, PB)는 그대로, 그 외 영어 단어는 쓰지 않는다. `잉크/ink` 금지(프로젝트 규칙).
8. 괄호 안 부연은 한 번만. 괄호 안에 다시 괄호 금지.
9. 줄바꿈은 브라우저에 맡긴다(`word-break: keep-all` 이 body 에 있다). `<br>` 로 줄을 맞추지 않는다.

## 7. 화면을 만들기 전 체크리스트

- [ ] 이 화면과 가장 비슷한 기존 화면은 무엇인가 → 그 화면의 구조·클래스를 그대로 잇는다.
- [ ] 새 색·새 글자 크기·새 간격을 하나라도 만들었나 → 만들었다면 토큰으로 바꿀 수 있는지 본다.
- [ ] 안내문을 소리 내어 읽었을 때 현장 반장이 쓸 말인가.
- [ ] 좁은 창(900px)에서 표가 잘리는가, 페이지가 가로로 흐르는가.
- [ ] 브라우저에서 실제로 열어 봤는가(구조 검증만으로는 렌더 순서·조합 회귀를 못 잡는다).

## 8. 레퍼런스

아직 없음. 현장에서 "이런 느낌"이라고 고른 화면 2~3개가 생기면 여기에 링크·캡처와 함께
"무엇을 가져올지(색 대비·밀도·표 스타일)"를 적는다. 그 전까지는 이 문서의 규칙이 레퍼런스다.
